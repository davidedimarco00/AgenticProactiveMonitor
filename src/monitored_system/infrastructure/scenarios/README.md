# Controlled Failure Scenarios

The scenarios in this directory inject reproducible faults into the monitored Notes Platform while normal synthetic user traffic continues to run.

## Base state

The normal workload is generated by `traffic-generator` while all services remain available and no controlled fault is active.

To restore the complete monitored system to this state:

```powershell
.\infrastructure\scenarios\reset-to-base.ps1
```

## Available scenarios

### cpu-spike

Target: `processing-service`

Starts a bounded number of CPU-bound workers. The expected OpenSearch detector is `CPU-processing-service`, based on `docker_container_cpu.usage_percent`.

```powershell
.\infrastructure\scenarios\cpu-spike\start.ps1 -Workers 4
.\infrastructure\scenarios\cpu-spike\stop.ps1
```

### memory-leak

Target: `worker-service`

Allocates and retains memory progressively. The expected OpenSearch detector is `RAM-worker-service`, based on `docker_container_mem.usage_percent`.

```powershell
.\infrastructure\scenarios\memory-leak\start.ps1
.\infrastructure\scenarios\memory-leak\start.ps1 -TotalMB 768 -StepMB 32 -StepSeconds 2
.\infrastructure\scenarios\memory-leak\stop.ps1
```

### high-latency

Target: `processing-service`

Adds a runtime processing delay without rebuilding or restarting the service.

```powershell
.\infrastructure\scenarios\high-latency\start.ps1
.\infrastructure\scenarios\high-latency\start.ps1 -DelayMs 2500
.\infrastructure\scenarios\high-latency\stop.ps1
```

### data-service-down

Target: `data-service`

Stops the persistence service to simulate complete downstream unavailability.

```powershell
.\infrastructure\scenarios\data-service-down\start.ps1
.\infrastructure\scenarios\data-service-down\stop.ps1
```

Each fault scenario includes a `scenario.yaml` ground-truth description. The current OpenSearch anomaly detector set is metric-based and contains only CPU and RAM SINGLE_ENTITY detectors. Therefore CPU and memory scenarios have dedicated detectors, while latency and availability scenarios are retained for diagnostic evaluation using telemetry and application logs and for future detector extensions.
