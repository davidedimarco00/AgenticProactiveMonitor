# Controlled Failure Scenarios

The scenarios in this directory inject reproducible faults into the monitored Notes Platform while normal synthetic user traffic continues to run.

## Base state

The normal workload is generated by `traffic-generator` while all services remain available and no controlled fault is active.

```powershell
.\infrastructure\scenarios\reset-to-base.ps1
```

## Available scenarios

### cpu-spike
Target: `processing-service`

Expected detector: `CPU-processing-service`, based on `docker_container_cpu.usage_percent`.

```powershell
.\infrastructure\scenarios\cpu-spike\start.ps1 -Workers 4
.\infrastructure\scenarios\cpu-spike\stop.ps1
```

### memory-leak
Target: `worker-service`

Expected detector: `RAM-worker-service`, based on `docker_container_mem.usage_percent`.

```powershell
.\infrastructure\scenarios\memory-leak\start.ps1
.\infrastructure\scenarios\memory-leak\stop.ps1
```

### network-latency
Target link: `api-gateway -> processing-service`

Normal traffic traverses a dedicated Toxiproxy TCP proxy with no active toxic. The scenario adds deterministic latency and optional jitter to that path. This approach works on Docker Desktop without depending on the host kernel exposing the Linux `sch_netem` qdisc.

Expected detector: `NETLAT-api-gateway-processing-service`, based on `network_service_latency.response_time`. ICMP `ping` remains available as an independent raw-network reference and `inputs.net` keeps interface counters.

```powershell
.\infrastructure\scenarios\network-latency\start.ps1 -DelayMs 250
.\infrastructure\scenarios\network-latency\start.ps1 -DelayMs 250 -JitterMs 25
.\infrastructure\scenarios\network-latency\stop.ps1
```

### high-latency
Target: `processing-service`

Adds an application-level runtime delay before downstream calls. Unlike `network-latency`, the delay is introduced inside the application.

```powershell
.\infrastructure\scenarios\high-latency\start.ps1 -DelayMs 2500
.\infrastructure\scenarios\high-latency\stop.ps1
```

### data-service-down
Target: `data-service`

```powershell
.\infrastructure\scenarios\data-service-down\start.ps1
.\infrastructure\scenarios\data-service-down\stop.ps1
```

Each fault scenario includes a `scenario.yaml` ground-truth description. All OpenSearch Anomaly Detection detectors remain SINGLE_ENTITY.
